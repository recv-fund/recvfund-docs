# Onboarding guide

This guide takes a fresh installation from the signup page to a confirmed test payment and a first sweep. It assumes the server is installed and healthy; see the [Deployment guide](/deployment-guide/introduction/) if it is not.

Everything below happens in the dashboard. Nothing in this guide requires shell access to the server except a restart, and the installer does that for you.

## The steps

| Step | Page | What it does |
| --- | --- | --- |
| 1 | [Root account setup](/onboarding-guide/root-account-setup/) | Create the owner account and first project at `/signup`, sign in, set the site URL and email delivery, invite teammates. |
| 2 | [Node configuration](/onboarding-guide/node-configuration/) | Enter the recv.fund program ID (Solana) or factory address (Robinhood Chain) for each network, check the RPC nodes, review the currency catalog. |
| 3 | [Hot wallet](/onboarding-guide/hot-wallet/) | Generate or import the one key the server holds, assign it to the project, fund it with SOL or ETH. |
| 4 | [Merchant registration](/onboarding-guide/merchant-registration/) | Register the project on-chain with one transaction from your browser wallet: cold wallet (settlement address) and sweeper. The fee is fixed for the registration at this point. |
| 5 | [Test payment](/onboarding-guide/test-payment/) | Create a customer and a payment link, pay it, watch it confirm. |
| 6 | [Funds sweeping](/onboarding-guide/funds-sweeping/) | Move deposit balances to the settlement wallet, automatically or by hand. |

The hot wallet comes before registration because registration writes the hot wallet address on-chain as the merchant's sweeper. The dashboard refuses to prepare a registration until an active hot wallet is assigned to the project for that chain family.

Steps 2, 3 and 4 repeat for every chain you want to accept payments on. Step 4 also repeats for every project.

## The setup guide in the dashboard

The **Overview** page opens with a **Set up payments** panel that follows the same order as this guide. It shows what's done and what's left for the selected project, explains each step in a sentence or two, and links to the page where you do it. It doesn't change anything itself.

The panel starts with a one-line summary of how money moves: the customer's wallet sends to that customer's deposit address, your hot wallet later sweeps it to your cold wallet, and the fee is taken only at the sweep. Then it lists these steps:

1. **Site URL**: the address payment links and emails point to.
2. **RPC node URL for each network**: how your server reads each blockchain.
3. **recv.fund contract address**: the program ID (Solana) or factory address (Robinhood Chain). On a testnet install, the panel shows the published test addresses. Once an address is set, the panel shows the fee for new registrations.
4. **Hot wallet**: assigned to the project, with some SOL or ETH for network fees.
5. **Cold wallet and on-chain registration**: the one transaction you sign and pay for with your browser wallet.
6. **Accepted currencies**: the tokens customers can pay with in this project.
7. **Test payment**: done once a payment of the project reaches `FILLED` or `OVER_FILLED`.
8. **Email (SMTP)**: optional; only payout approvals need it.

Steps 2 through 6 list every active network. A step counts as done once one network is ready, so check the per-network lines for any other network you want to accept. The **Site URL** step stays open when the site URL differs from the address you opened the dashboard at, because payment links would point to the wrong place.

Steps 4 through 7 belong to a project. When the sidebar shows **All projects**, choose a project in the panel to see them. A teammate whose role can't read a setting sees "Visible to owners and admins" (or a similar note) instead of a status. The panel hides itself when every required step is done. **Hide guide** and **Show guide** toggle it, and the browser remembers the choice.

## What you need

| Item | Why |
| --- | --- |
| The signup URL printed by the installer | It is `https://<your site>/signup`. It works only until the first account exists. |
| A browser wallet with a little SOL or ETH | Registration is an on-chain transaction signed in your browser. Solana: Phantom, Solflare or another injected Solana wallet. Robinhood Chain: MetaMask or another injected EVM wallet. This wallet becomes the merchant admin key; keep it. WalletConnect is not available in this release, so use a desktop browser with a wallet extension. |
| A cold wallet (settlement address) per chain | The address that receives your funds when deposits are swept. Only a transaction signed by the merchant admin wallet can change it later. |
| The recv.fund program ID (Solana) or factory address (Robinhood Chain) for each network | Entered once under Nodes. The server verifies the code at the address against the build it ships with. The test network addresses are listed under [Networks and tokens](/support/networks/#program-addresses). |
| An SMTP server | Payout approval codes are sent by email. Payments and sweeps do not need email. Configure it early so the test email and payouts work when you get to them. |
| Native currency for the hot wallet | The hot wallet pays the network fee of every sweep and sends payouts. On testnet, use a faucet. |

On testnet installs the chains are Solana devnet and Robinhood Chain testnet, and every payment carries a test flag. See [Networks](/support/networks/) for the networks, chain IDs and explorers.

## What "ready to accept payments" means

A chain being listed in the dashboard does not enable checkout on it. For a project to accept a payment on a chain, all of the following must be true:

| Requirement | Where |
| --- | --- |
| The program ID or factory address for that network is configured and verified | Nodes → Deployed program |
| The project has an active merchant registration on that chain | Registrations |
| At least one currency of that chain is enabled for the project | Projects → Enabled currencies |
| A hot wallet for the chain family is assigned to the project | Hot wallets |
| The site URL is set | Installation → Site URL (needed to generate payment links) |

The checkout page lists only currencies whose chain has an active registration for the project. If the list is empty, the customer sees "No payment currencies are available."

## Who can do what

The owner account created at signup can do everything. If you invite teammates, note that only owners and admins can manage nodes, generate or import hot wallets and change installation settings. Project leads can assign an existing hot wallet, register on-chain, create payment links and queue sweeps for their projects. See [User management](/features/user-management/) for the full role table.
