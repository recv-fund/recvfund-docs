# Merchant registration

Open Registrations in the sidebar (`/wallets/deposit`). The page is titled "Merchant registrations". Any member can read it; owners, admins and project leads can register and manage.

## What registration is

A merchant registration is a record in the on-chain program, one per project per chain. It holds:

| Field | Set from | Can change later |
| --- | --- | --- |
| Merchant ID | 32 random bytes generated by your server | No |
| Admin | The browser wallet you connect | No |
| Settlement wallet | The address you type | Yes, signed by the admin |
| Sweeper | The hot wallet assigned to the project | Yes, signed by the admin |
| Active | Set on registration | Yes, signed by the admin |

The program moves funds only to the settlement wallet and the fee collector. Customer deposit addresses are derived from the program and this record (a program-derived address on Solana, a CREATE2 address on Robinhood Chain), so the registration must exist before a customer can be given an address. The admin key stays in your browser wallet; the server prepares unsigned transactions and never sees a private key.

## Before you start

- The program address for the network is configured under Nodes. Otherwise the form shows "An installation administrator must configure this network's deployed program in Nodes before registration."
- An active hot wallet of the right family is assigned to the project. The form links to "Manage hot wallet assignments". Preparation is refused without it.
- One project is selected in the sidebar workspace selector. With "All projects" selected the page only lists registrations.
- Your browser has an injected wallet with a little native currency for the transaction fee: an EVM wallet such as MetaMask for Robinhood Chain, or Phantom, Solflare or another injected wallet for Solana. WalletConnect is not available in this release. On Robinhood Chain the wallet must be switched to the right chain (`4663` mainnet, `46630` testnet) before signing.

## 1. Prepare registration

Fill in the "Prepare registration" form:

1. **Network**: the chain to register on.
2. **Merchant admin address**: press "Connect browser wallet" to fill it from the wallet, or paste it. This is the key that controls the record from now on.
3. **Settlement address**: the wallet on that network that will receive your funds. Type it carefully; it is checked for format, not ownership.
4. **Label (optional)**: a name for the row.

Press "Prepare registration". The server locks the project and chain, creates a registration row in `pending` with a new merchant ID, and returns the transactions to sign. The row appears in the "Registered merchants" table (Project / network, Settlement, Sweeper, Status, Actions).

## 2. Sign

The "Sign and confirm" panel opens. It shows the program fees that will apply ("Program fees: checkout N bps · sweep N bps") and the transactions, one block each with the signer, the contract and a button.

- **Robinhood Chain**: two steps, "1. Register merchant" and "2. Assign sweeper". Press "Sign step 1", approve it in the wallet, and wait; the page polls for the receipt for up to three minutes and enables step 2 when the first transaction is included. If it is still pending, the button changes to "Check inclusion". A reverted transaction stops the flow; prepare again.
- **Solana**: one step, "1. Register merchant and assign sweeper". The wallet signs and sends a single transaction containing both instructions.

The wallet must have the signer account selected and be on the transaction's chain; otherwise the page refuses with a message saying which account or chain to switch to. Each submitted hash is shown in the block. Write the last hash down if you might leave the page.

## 3. Confirm on server

Signing puts the record on-chain; the server does not know until you tell it. The field "Transaction hash to verify" is prefilled with the last submitted hash. Press "Confirm on server".

The server reads the transaction from the RPC pool and checks: the network, that the program at the address is the supported build, that the transaction succeeded, that it was signed by the merchant admin and contains a registration or sweeper instruction for this merchant, that it has the required confirmations (1 on Solana, 12 on Robinhood Chain by default), and that the merchant record on-chain now shows the expected admin, settlement wallet, sweeper and active flag. If confirmations are still short, the response says so; wait and press the button again. On success the row's status becomes `active`.

On Robinhood Chain the server never marks a registration active after only the first of the two transactions.

## Leaving and resuming

Local step state is dropped when you leave the page, but the pending row stays. Press "Manage" on it and then "Resume registration". The server reuses the original admin and settlement addresses (they cannot be changed on a pending row) and returns only the steps that are not yet on-chain. If everything is already on-chain, the panel says so and you only need to enter a hash and confirm.

## After registration

- Checkout on that chain is open for the project: the currencies of that chain that are enabled under Projects appear on the checkout page, and a customer who picks one is assigned a deposit address.
- The sweeper is the hot wallet's address. The sweep worker can now sign sweeps for this merchant.
- The row shows `active`. Its merchant ID and admin address are visible under "Manage".

Repeat the whole page for each other chain, and for each other project. Each combination gets its own merchant ID.

## Managing an active registration

Press "Manage" on an active row. Every change is an unsigned transaction prepared by the server, signed by the merchant admin wallet in the same "Sign and confirm" panel, and then confirmed with "Confirm on server", which reads the actual on-chain state back into the database.

| Action | Form | Notes |
| --- | --- | --- |
| Change settlement wallet | "New settlement address", then "Prepare settlement update" | Future checkout payments and sweeps go to the new address once confirmed. |
| Update sweeper | "Assigned hot wallet", then "Prepare sweeper update" | Assign the new hot wallet to the project first; the list shows only active wallets assigned to this project for this chain family. |
| Prepare deactivation / Prepare activation | One button | An inactive registration rejects new checkout payments. Sweeps still work, so funds already at deposit addresses can always be moved to the settlement wallet. |
