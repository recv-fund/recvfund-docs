# Checkout endpoints

The hosted checkout page at `/payments?reference_id=<uuid>` is built on four public endpoints. You can call them from your own page instead. They take no API key: the reference id is the only credential, so treat it as you would treat any payment link.

All four are rate limited per client IP address by `rateLimit.checkout.perMinute` (default 120 per minute). Responses are bare JSON with `Cache-Control: no-store`; errors are `{ "code": "...", "message": "..." }` as described in the [Introduction](/api-integration/introduction/). Path parameters must be version 4 UUIDs.

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/v1/checkout/{reference_id}` | Payment summary, branding, available currencies with prices, the current selection and quote. |
| POST | `/api/v1/checkout/{reference_id}/select` | Select a currency: assigns the deposit address for its chain and creates a quote (exact token amount). |
| POST | `/api/v1/checkout/{reference_id}/payTransaction` | Build the unsigned transaction(s) for a wallet payment against the current quote. |
| POST | `/api/v1/checkout/{reference_id}/confirm` | Submit a transaction hash for verification on chain. |

Unlike the keyed endpoints, these use camelCase keys and lowercase states.

## POST `/api/v1/checkout/{reference_id}/select`

Selects a currency for the payment. The server assigns the customer's deposit address on that chain (creating it on first use), fetches a fresh price, computes the token amount for the remaining USD balance, and stores a quote. The response is the same object as `GET`, with `selected` filled in.

```bash
curl -X POST https://<your-site>/api/v1/checkout/c80f5363-0397-4761-aa1a-3155c3a21470/select \
  -H "Content-Type: application/json" \
  -d '{"currencyID": 3}'
```

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `currencyID` | integer | yes | A `currencyId` from `currencies[]`, at least 1. |

`200 OK` with the `GET` object.

Quote rules:

- Amount = remaining USD ÷ price, in base units, rounded up once to an integer. Stablecoins use the fixed catalog price.
- A quote lives for `payment.quoteTtlSeconds` (default 300; 30 to 3600), shortened by the payment's expiry and, for non-stablecoins, by the price's freshness deadline (`price.maxAgeSeconds`, default 300).
- Selecting again creates a new quote and a new `quoteId`. Selecting a different currency after a transfer has been detected is rejected.
- For a deposit-address payment the customer sends exactly `selected.amount` of the currency to `selected.address`. The watcher credits what actually arrives, at the price observed on first detection, not the quoted amount.

Errors:

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `BAD_REQUEST` | `currencyID` missing or not a positive integer; the currency is not available for this payment; the amount cannot be represented in this currency (too small or above the chain's maximum). |
| 404 | `NOT_FOUND` | Unknown reference id. |
| 409 | `CONFLICT` | Project or customer inactive; payment closed or expired; currency availability changed during the request; the currency differs from the selected one and a transfer is already detected; the quote would already be expired (retry). |
| 429 | `RATE_LIMITED` | Per-IP limit exhausted. |
| 503 | `UNAVAILABLE` | No fresh price for a non-stablecoin, or an invalid `payment.quoteTtlSeconds` setting. |

## POST `/api/v1/checkout/{reference_id}/payTransaction`

Builds the unsigned transaction(s) a wallet must sign to pay through the recv.fund program. Requires the current quote.

```bash
curl -X POST https://<your-site>/api/v1/checkout/c80f5363-0397-4761-aa1a-3155c3a21470/payTransaction \
  -H "Content-Type: application/json" \
  -d '{
    "currencyID": 7,
    "payer": "0x9f8e7d6c5b4a39281706f5e4d3c2b1a09f8e7d6c",
    "quoteId": "0b6c2f0e-9a3d-4c1e-8f7a-2d5b6e1c9a4f"
  }'
```

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `currencyID` | integer | yes | Must equal `selected.currencyId`. |
| `payer` | string | yes | The customer's wallet address on that chain, at most 128 characters. |
| `quoteId` | string | yes | Version 4 UUID; must equal `selected.quoteId` and be unexpired. |

`200 OK`

```json
{
  "quoteId": "0b6c2f0e-9a3d-4c1e-8f7a-2d5b6e1c9a4f",
  "expiresAt": "2026-09-22T06:58:42.419Z",
  "transactions": [
    {
      "kind": "evm",
      "purpose": "Approve invoice amount",
      "from": "0x9f8e7d6c5b4a39281706f5e4d3c2b1a09f8e7d6c",
      "to": "0x5fc5360d0400a0fd4f2af552add042d716f1d168",
      "data": "0x095ea7b3…",
      "value": "0",
      "chainId": "46630"
    },
    {
      "kind": "evm",
      "purpose": "Pay invoice",
      "from": "0x9f8e7d6c5b4a39281706f5e4d3c2b1a09f8e7d6c",
      "to": "0x1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d",
      "data": "0x…",
      "value": "0",
      "chainId": "46630"
    }
  ]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `quoteId`, `expiresAt` | string | The quote the transactions were built for. |
| `transactions[]` | array | Ordered steps. Have the wallet sign and send each one, and wait for inclusion, before the next. |
| `transactions[].kind` | string | `evm` or `solana`. |
| `transactions[].purpose` | string | Label for the step: `Reset token allowance` (only when an existing allowance must be cleared first), `Approve invoice amount`, `Pay invoice`. Native ETH payments have a single `Pay invoice` step. |
| `transactions[].from` | string | The payer. |
| `transactions[].to`, `transactions[].data`, `transactions[].value`, `transactions[].chainId` | string | Present for `evm`: the call target, calldata, native value in wei and the chain id, as strings. |
| `transactions[].serializedTransaction`, `transactions[].lastValidBlockHeight` | string | Present for `solana`: the base64 serialized transaction to sign and the block height until which it is valid. |

The approval step is bounded to the invoice amount. The pay step calls the program with the invoice id derived from the reference id; the program splits the transfer between your settlement wallet and the fee collector in the same transaction. A wallet may sign the transaction after the quote expires; whatever lands on chain is credited at its verified amount.

Errors:

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `BAD_REQUEST` | Field validation; the amount exceeds the chain's supported range; the currency has no wallet payment (native SOL: use the deposit address). |
| 404 | `NOT_FOUND` | Unknown reference id. |
| 409 | `CONFLICT` | Project or customer inactive; payment closed or expired; `currencyID` or `quoteId` do not match the current quote, or the quote expired (select again); the currency has become unavailable; the remaining balance changed since the quote; the merchant registration is inactive; the invoice was already paid on this chain. |
| 429 | `RATE_LIMITED` | Per-IP limit exhausted. |
| 503 | `UNAVAILABLE` | The RPC pool could not build the transaction. |

## POST `/api/v1/checkout/{reference_id}/confirm`

Tells the server about a transaction hash so it can verify it on chain now instead of waiting for automatic discovery. The server reads the transaction from its RPC pool, matches program events to this invoice and merchant, and records the transfer. It never trusts an amount or a success claim from the client.

```bash
curl -X POST https://<your-site>/api/v1/checkout/c80f5363-0397-4761-aa1a-3155c3a21470/confirm \
  -H "Content-Type: application/json" \
  -d '{"chainID": 2, "txHash": "0x7b1e…"}'
```

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `chainID` | integer | yes | The `chainId` of the currency paid with, at least 1. |
| `txHash` | string | yes | Transaction hash or Solana signature, at most 128 characters. |

`200 OK`

```json
{ "state": "open", "filledAmountUsd": "0.000000" }
```

| Field | Type | Meaning |
| --- | --- | --- |
| `state` | string | The payment state after recording: `open`, `partially-filled`, `filled`, `over-filled` or `cancelled`. Stays `open` until the chain's confirmation threshold is reached; the confirmation worker moves it on. |
| `filledAmountUsd` | string | Confirmed USD amount after this call. |

Repeating the call for the same hash is safe and returns the current state. The call also works after the quote has expired or the payment has been cancelled.

Errors:

| Status | `code` | Cause |
| --- | --- | --- |
| 400 | `BAD_REQUEST` | Field validation; no merchant registration on this chain; the transaction is unknown, failed, or contains no payment event for this invoice and merchant. |
| 404 | `NOT_FOUND` | Unknown reference id. |
| 409 | `CONFLICT` | The event's token is not in the chain catalog. |
| 429 | `RATE_LIMITED` | Per-IP limit exhausted. |
| 503 | `UNAVAILABLE` | RPC or price lookup unavailable; nothing is recorded. |

## Building a page

1. `GET` the checkout. If `available` is `false` or `state` is not `open` or `partially-filled`, show the state and stop.
2. Show `currencies[]`; hide entries with `priceUnavailable`. Offer a wallet button only where `walletPayment` is `true`.
3. On choice, `POST select`. Show `selected.address` and `selected.amount` (and a QR code of the address) for a transfer, or call `payTransaction` and hand the steps to the wallet.
4. After each wallet step is sent, call `confirm` with its hash. Poll `GET` every few seconds for `state` and `filledAmountUsd`; the per-IP limit of 120 per minute allows a five second interval with margin.
5. When `state` leaves `open`, show the result. Your server learns the same through the [webhook](/api-integration/payments-api/webhook/) and confirms with [Payment status](/api-integration/payments-api/payment-status/).

WalletConnect and ERC-20 `permit` flows are not implemented in this release; the hosted page uses injected browser wallets.
